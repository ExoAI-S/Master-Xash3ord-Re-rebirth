# Daragoth Plains — complete Windows game

Download **MSR-Daragoth-Complete-2026-10-03.zip** and extract the entire archive
to a new writable folder. Open **MSR-Launcher.exe** or **Play-MSR.cmd**, then
choose **Play local**. New local realms start in Daragoth. Everyone joining a
host should use this same release.

## What is included

- The familiar Daragoth starting valley opens continuously into rolling plains,
  with no loading screen at the connection.
- Denser grass, mixed trees, apple trees, a matching road, natural boundary
  slopes, a creek and the small village of Greenhollow with walking residents
  and furnished buildings.
- Rideable horses and a stablemaster who lends separate horses to players.
  Horse loans last for the session; they are not persistent character possessions.
- Thirty wilderness encounter areas activate around nearby living players.
  A shared limit of sixteen managed enemies and staggered spawning bound the
  load. Enemies use existing scripts; this does not replace the MScript system.
- Nearby foliage stays detailed while distant decorative grass, bushes, rocks
  and trees gradually disappear. Terrain, buildings, actors, items and collision
  remain. Set `ms_scenery_distance 0` in the console to disable this optimization,
  or `ms_scenery_distance 1` to restore it. `cl_showfps 1` displays gameplay FPS.
- Existing BigWorld regions, inventory/character/world-map menus, Dungeon Master
  tools, Erratic Lightning changes, FN persistence and profile recovery remain.

Press **P** for inventory, character and world-map tabs. Use the stablemaster's
interaction near the stables for a horse. The local host's settings file can
select other starting maps; existing host settings are preserved.

## Saves and hosting

Extract into a new folder and keep the previous installation until your own
characters are confirmed. Choose **Recover characters** and select your own
previous folder/profile if necessary. A player profile identifies the player;
the FN database on the host stores that host's characters. Hosting locally
does not copy the shared Internet host's database. See **RECOVER-CHARACTERS.md**.

**Play-Realm-One.cmd** and **Play-Realm-Two.cmd** retain the shared Internet
realm addresses. Those hosts and tunnels must be online and updated; publishing
this ZIP does not update a running server. LAN players can use the host PC's LAN
address. Internet hosting still requires suitable port forwarding or a tunnel.

The old BigWorld installer and uninstaller are retired in this integrated
release. Use the entire previous installation for rollback, with its save
backups, rather than mixing old DLLs or maps into this one.

## Validation and remaining limits

This is an **x86 Debug build**, with matching engine/client/server symbols.
Native checks covered map startup, all thirty encounter registrations,
near/far activation, the sixteen-enemy cap, retirement and return spawning,
and scenery comparisons at plains and village viewpoints. Portable packaging
checks are recorded separately in **RELEASE-MANIFEST.json** and the release
verification report.

At 1280×720, the same client measured about 39 FPS with scenery fading disabled
versus 85–88 FPS enabled in a rotating-view `timerefresh` test at one plains
position. This is renderer throughput, not a promised gameplay frame rate.
See **Docs/Daragoth-Scenery-Distance-Playtest.md** for the full comparison.

Combat rewards, death/respawn timing, multiplayer stress and traversal of every
encounter area are not fully verified. The conservative retirement policy may
retain an enemy and consume a slot; one archer did so during testing. Extended
riding and foliage in water reflections need further visual testing. A screen
pattern can be visible during scenery fading. Greenhollow's residents do not
yet provide shop or inn services.

The named release ZIP contains the runnable game, bundled runtime, source and
editable artwork. GitHub's automatic **Source code** download is for developers.
The ZIP calls the SDK folder **Source**; the Git checkout calls it **Full-Source**.
To run repository-relative development tests from the ZIP, rename that folder
to **Full-Source** in a separate development copy. Map regeneration also needs
the pinned original assets and intermediate inputs described by the builders;
the source snapshot alone is not a one-command map rebuild.
Component licenses and asset notices remain separate; this release does not
relicense the combined game. See **THIRD-PARTY-NOTICES.md** and the artwork's
included license files.
