# Continuous Daragoth development prototype

This separate builder preserves the original Daragoth starting area and opens its northern road into the larger riding plains. The connection is a spatial BSP join at world Y=3216. Walking across it does not use a teleport, fade, or map load. This is an isolated development candidate, not a public release or a replacement for the installed game.

The original BSP and its current `.ent` override are read-only inputs. The original character creation spawn remains `(-864,-3856,3200)`. The Helena/Edana, Nashalrath and mines exits remain present. The old Deralia exit at Y=3232 is removed and its destination metadata is attached to a new trigger at the far northern end of the plains. Both original gate guards remain present. Decorations behind the old gate are removed to open the route.

The frozen `Daragoth-Plains` generator and assets remain unchanged. The builder executes a transient generator adaptation into a separate output directory: a flat southern approach at local Z=384, a smooth height blend into the existing plains, and a sky shell 640 units south of the eventual cut. The road is translated to meet the original road at X=1528 and floor Z=3072. Cropped straddling render faces receive correctly repacked lightmaps. Original 16-unit lightmaps and new 64-unit lightmaps retain their respective sample sizes. All four world collision trees use the same axial join. Original visibility is retained away from the portal and conservatively extended across the join near the northern road.

Example from the repository root (use an isolated output directory):

```powershell
python Design-Source/Daragoth-Expanded/build_expanded.py --original C:/MSR/Portable-Package/game/msr/maps/daragoth.bsp --ent C:/MSR/Portable-Package/game/msr/maps/daragoth.ent --out ../daragoth-development/expanded --tools C:/Users/cptki/Documents/Codex/MSR-BigWorld/src/build-tools/Release/msr/devkit --stone-facing
python Design-Source/Daragoth-Expanded/build_script_library.py --base ../daragoth-development/runtime/game/msr/scripts.pak --out ../daragoth-development/expanded/scripts.pak
```

`--reuse-compiled` reuses the previously compiled entry variant while rebuilding the join. Use `--stone-facing` for the current preview: it writes `daragoth_expanded_stonefaced.bsp` without replacing earlier frozen candidates. It includes reciprocal cross visibility, the original-only spawn pool, lit procedural rock facing and upper SKY closure, with the stock clockwise brush winding required by Xash's `GL_FRONT` culling. The earlier `--caps` output lacked sky closure; the `--sky-close` output fixed stale framebuffer pixels but its incorrectly wound rock polygons were removed by OpenGL. Both are historical visual failures. The output report records input hashes, offsets, crop counts, lightmap repairs, visibility changes, and static hull/index validation. Native movement and rendered cliff views are separate required checks.

For this preview, set `ms_region_unload_time 0` so all adjoining content stays loaded. Adjacency-aware region preloading is future work. Copy the full runtime `liblist.gam` when staging the playable preview; the small marker inside `variant/msr` exists only for offline map compilation. Private test identities and private FN saves belong to the parent staging workflow; this builder never modifies them.

The intended private runtime alias is `daragoth.bsp`, keeping the ordinary startup name and the reciprocal entrances from neighboring maps. Back up and hide that private runtime's old `daragoth.ent` sidecar before staging: an existing sidecar would override the combined BSP's embedded entities. Do this in both private client/server roots. The live `C:/MSR` original map and sidecar stay untouched. The new optional `daragoth_expanded` script entries support launching the source output by its direct filename; the `daragoth` alias uses the original startup plus logical region scripts and needs only the existing plains additions.

The original Deralia trigger has no `desttrans` key. This absence is preserved exactly; when running the intended `daragoth` alias, its ordinary fallback remains the original map name. The source BSP and ENT are pinned by SHA-256 before entity-index edits. Modified originals must be surveyed again, rather than silently applying these removals to a different version. The build report records each removed entity's model, bounds/origin and reason. The preview removes one decorative wall that straddles the cut; its south section can be restored with a render-only crop after visual QA.

The flat road joins at equal floor height. The stone-faced candidate renders the surrounding solid cut edges and upper sky coverage while leaving the road open below the original ceiling. Loaded characters crossed both directions on foot and mounted without a map load or fade, and native southern views confirm that rock draws without sky-at-ground gaps or stale framebuffer pixels. This proves a working prototype connection; the broad flat gray facings and jagged cut silhouettes still need authored natural cliff relief and transition landscaping. The remote Deralia entrance scene, regional quests, external travel and performance on other PCs have not been tested. The original low sky ceiling and all-regions-loaded prototype lifecycle also remain limitations. Broader gameplay and rendering QA must pass before public installation or release.

`Development-Tests/report_daragoth_continuous.py` writes the permanent sanitized preview report, defaulting to the stone-faced candidate. Pass archived successful native logs with repeated `--native-log` arguments and an optional private `--native-review` JSON containing only matching final-candidate visual and gameplay confirmations. It never copies raw log lines, names, profiles, credentials or screenshots. Missing checks remain pending. Mounted DC config markers alone cannot pass a test: actual loaded regions, rider origins on both sides and owner linkage are required. `--candidate capped` and `--candidate skyclosed` reproduce historical reports, including their native visual failures and incorrect stock brush winding. Earlier native tests cannot pass the new candidate because review hashes must match the selected frozen BSP.
